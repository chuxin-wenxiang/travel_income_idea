# 测算口径

所有金额人民币；默认值只是演示，不是市场报价。数据来源在模板中明确标记为未验证。

- 基础旅费 = 往返交通 + 每晚住宿 × 晚数 + 每日餐饮 × 天数 + 其他费用。
- 住宿减免 = 已确认金额与住宿费用中的较小值，不作为收入。
- 固定支出 = 基础旅费 − 住宿减免 + 固定经营投入。
- 订单容量 = floor(愿意工作总小时 ÷ 每单总工时)。计划单数按容量截断。
- 收入 = 订单数 × 每单价格。
- 全部支出 = 固定支出 + 订单数 × 每单变动成本。
- 现金结余 = 收入 − 全部支出，负值为仍需承担的费用。
- 相比纯旅行改善 = 现金结余 + 基础旅费。
- 回本单数 = ceil(固定支出 ÷ (单价 − 每单变动成本))；单笔毛贡献 ≤ 0 时显示无法回本。
- 保守情景用计划单数的一半向下取整；零订单情景没有经营收入。两者都不是置信区间。
- 预算缺口按所有收入最后才到账估算：max(0, 全部计划支出 − 可用预算)。这不是分日现金流模型。
- 剩余可安排时间按每日 8 小时减工作小时展示，仅作规划提示，未扣交通与个人活动。

换宿若以班次为条件，用户应先确认对应减免金额；网页不根据班次自动承诺减免。若减免可能失效，应另测 saving=0。固定投入不预测转卖残值。未建模的税费、保险、平台费需加入 other、setup 或 variable。

## 命令行输入示例

```json
{"days":4,"nights":3,"budget":2500,"workHours":12,"transport":500,"nightly":180,"food":80,"other":200,"setup":200,"price":350,"variable":30,"hours":3,"orders":3,"saving":0}
```

字段与网页一一对应。所有字段必填，未知值先询问或声明假设；负数、非有限数字、超过行程的晚数/工时、非整数订单拒绝计算。
