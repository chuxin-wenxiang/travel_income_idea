# 产品方向与验证计划

## 起点

发起者观察到：就业和收入预期的不确定性可能使旅行者更重视花费，而旅行愿望仍然存在。产品希望把旅行从单向支出，扩展为可以通过服务收入或费用减免降低净负担的活动。

这是待验证的产品假设，不是已证实的宏观因果结论。发起者提到“出行人次增加、景区人均消费下降”的报告观察，尚未提供具体报告与统计口径。不能把景区消费直接等同于全程旅游消费，也不能由人均消费下降直接推导未来出游人数下降。后续补齐同口径年份、样本、名义/实际价格与目的地结构，再判断。

## 核心任务

当我有出游愿望但预算紧张时，帮我找到符合能力、时间和承受范围的创收方式，并在付款出发前知道它是否可行。

成功分三层：减少净支出、覆盖全程成本、取得现金结余。三者都需要同时衡量劳动时间与旅行体验。不能为了“赚钱”把旅行变成用户不想要的高强度工作。

## 用户与机会范围（2026-10-29 纠偏）

核心不是异地求职，而是结合事件、人群、地点、时机与已有行程发现挣钱机会。收入可以来自商品差价、服务费、租赁、销售分成、作品授权；费用交换单独核算。既包括被动申请，也包括主动经营、提前获客、顺路交付与合作生意。

先广泛研究可能性，再按用户真实技能、资源、资金和时间筛选。四天行程、零摄影基础等仅为历史测试画像，不是产品固定目标用户。招聘网站和Jobicy是可选来源，不能主导机会范围。

完整商业切口、信息源分层与算账边界见 [机会地图](opportunity-map.md)。原100条保留，新增40个细化/补充切口，不用未经证实的高收益数字填充推荐。

## 为什么网页 + Skill

网页承担比较、调参、计算和导出，用户能检查每个数字。Skill 承担补齐约束、检索核验、沟通与个性化行动方案。两者共享数据和确定性计算器。v0.3 网页没有模型调用，推荐是技能筛选，不伪装成智能预测。

## v0.3 已实现

6 个演示模板、100 种灵感检索、成本测算、容量限制、三情景比较、本地方案导出、可安装 Skill 和命令行计算器。

## 后续阶段

1. 需求验证：访谈近期因预算调整旅行的人；区分预算不足、收入焦虑、不愿劳动与找不到客户。观察用户是否愿意为真实订单准备作品与报价。
2. 人工试点：先比较一个城市内不同收入机制的商业场景，再选具体事件和买方。服务可先拿订单；商品生意需核验交易点位、货源、小批量需求与库存现金风险。
3. 数据闭环：机会来源、核验时间、失效时间、资格、订单状态、实收、退款与工时。过期机会下线；实际样本不足时不发布收入预测。
4. 服务化：真实机会连接、行程价格接入、订单和结算；再决定是否需要模型 API、账户与支付。

## 验证指标（尚未设定达标数值）

- 从浏览方案到取得有效需求确认的比例。
- 实际净支出改善、全程费用覆盖比例，并同时报告零收入比例与中位数。
- 获客和交付总工时、实际游玩时间、旅行满意度。
- 退款、争议、核验失败与因预算不足主动放弃的情况。

观察到真实重复使用与可靠交付后再考虑收费。未来可验证服务费或工具订阅；避免靠鼓励用户增加风险支出来变现。

## v0.4 落地进展

已增加机会录入与持久保存、跟进状态、确认依据、独立公开远程职位接入、工作台备份恢复、带来源的旅行计划与实际结果记录。真实来源覆盖有限；国内短期招募仍以用户提供原文为入口。下一步应通过真实用户试用决定优先接入的国内来源，而不是继续增加未经核验的模板。
