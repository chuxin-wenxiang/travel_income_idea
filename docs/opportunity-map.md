# 旅行与出行挣钱机会地图

## 本轮纠偏

项目不是“旅游地找工作”，而是发现**因人群、事件、地点、时机、信息或供给差异形成的收入机会**，再决定是否值得带着商品、服务或资源出发。招聘只是取得订单的一种途径。

原 `data/100_玩法完整清单.json` 的 100 条全部保留。原表已经有演唱会周边、音乐节摆摊、漫展道具、代取展会资料、调研、群演、代购、租赁和内容等。这里补充 40 个具体切口，其中有原思路细化，不能简单宣传成“140种不同生意”。历史收入区间没有证据，不当作报价或收益预测。

不预先把用户固定为零基础、四天旅行、每天工作六小时。先展示可能性，再按用户真实资源选择；不会为了适配当前已经实现的功能而排除经营、交易和主动获客。

## 怎样发现机会

事件/季节/目的地 → 谁会来 → 在什么时刻缺什么、愿为哪种便利付钱 → 提供商品/服务/租赁/授权/撮合/交换 → 如何触达买方 → 验证成交 → 核算净现金与剩货 → 决定行程。

“有演唱会”证明事件存在，不证明应援棒一定能卖；“有人发招募”也不是必需条件。主动经营的关键证据是客群需求、可交易位置、商品适配、货源和小规模成交。主办方是否已送同类物品、附近多少竞争者、进出场动线、售卖窗口，都会改变生意。

## 信息源需要分成五层

1. **机会触发源**：演出/展览/赛事档期、景区季节变化、商业街和商场活动。先发现“哪里、何时、聚集谁”。
2. **需求证据源**：观众公开问答、当地实地观察、同类销售反馈、客户委托、小额预订。热度、评论数和售罄不能直接换算销量；不用私人群聊天自动建公共库。
3. **交易条件源**：主办方招商、场馆规则、摊主招募、附近商家合作、服务商准入。要验证在哪能经营、卖什么、收费与退改，不默认展会门口可摆摊。
4. **供给与成本源**：具体供应商报价、样品、最小起订量、到货时间、瑕疵退换与正版凭据；交通、住宿、摊位、设备、物流成本另计。
5. **成交与结算源**：真实预订单、成交记录、退款、佣金结算与剩货处置。经营预测和已确认订单分开。

招聘平台主要覆盖少量人员需求，不能替代前四层。平台存在也不等于获得抓取许可；外部用户用自己的账户完成准入，产品不依赖作者的私有账号或群资源。

## 商品生意与服务订单必须分别算账

商品生意的现金变化 = 实收销售款 + 实收退货/清仓款 − 全部进货款 − 进货物流 − 摊位/合作费 − 往返与住宿等旅费 − 支付手续费/税费 − 其他实际开支。

未卖掉的库存不是现金；可退货也不能在退款未确认时直接当现金回收。单件毛利不能直接当整趟利润；先买100件只卖40件时，现金支出仍包括100件。按“零销量/少量售出/计划售出”列现金情景，另列期末库存数量及不确定的残值。库存经济价值与现金结余不得混用。

例子仅说明算法，非进货报价或销量预测：进100件、每件4元，共400元；每件卖10元，实际卖60件，收600元；物流50元、摊位100元、旅行200元，则现金变化是 **-150元**，另有40件剩货。若错误地只扣已售60件的货款，会算出+10元。前者才反映本趟资金实际变化。

服务按获客、等待、往返、交付和修改总工时算；租赁把押金与租金分开；内容分成在出售/结算前不当现金；换宿只计实际减免。

**当前 `web/engine.mjs` 是服务单数测算器，不是进销存模型。它会按成交单数计算单件成本，不能直接拿来评估预先进货摆摊。** 本轮先纠正机会研究与商业逻辑，商品生意未接专用计算器前使用上述独立表，不伪装已有能力。

## 杭州下一轮怎样试，而非换一个城市继续找岗位

- 演唱会/动漫展：找具体档期与客群，再比通用应援用品、收藏配件、合影打印、妆造修补。先查是否已赠送同类物品、商家招募及附近合作点位。
- 文旅/花季/周末市集：比原创纪念物、租赁道具、家庭应急小件与现有摊主寄售。公开热度只作线索，必须找付费需求。
- 商贸展会/产业出行：比受托逛展、样品记录、展商内容、采购合单；先在出发地找需要到场服务的买方。
- 民宿与餐饮：比内容交付、外语信息整理、店铺工具改造、技能换宿；找店主愿意买的明确成果，而不是只搜“招兼职”。

先覆盖“卖商品、卖服务、利用顺路、资产/内容、费用交换”几种不同收入机制，再选具体场景小规模验证。停止条件不是“招聘网站没岗位”，而是没有可触达的买方、没有交易条件，或成本与需求证据不足以支持试做。
